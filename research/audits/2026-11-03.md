## Findings
1. **`apexpm/registry.py:94-100` `mode_for` — a `paper`-status strategy can trade real money.** With PAPER=false and DRY_RUN=false, `paper`/`live` status returns "PAPER", but `Broker` builds `TradingClient(paper=cfg.paper)` (`broker.py:45`), so it hits the live endpoint. GOVERNANCE says paper status is "Paper only". Only reachable in the LIVE config, which warns for 10s at startup. Fix: `if st == "paper" and not cfg.paper: return "DRY_RUN"`. Not applied because it changes order behavior.
2. **`apexpm/loop.py:686-695` — the option premium stop depends on a quote.** If `obroker.mark()` returns None (no bid or ask, API error), the premium stop and target are skipped for that scan. The `under_stop` check also needs a fresh stream price. Only the time exits (max hold, flat-by, expiry cutoff) are guaranteed. A position in an illiquid contract can sit through a premium-stop breach until the cutoff. Fix: if the mark is missing for N consecutive scans, log an error and exit on the time rule, or fall back to the last bid.
3. **`apexpm/profiles.py:112-113` — the positions exception overrides the hyper one-position rule.** `positions_exception_on` raises `max_positions` to 5 even in the hyper band (under $1k, where the rule is 1 position at up to 100% of equity). Fix: don't lift the cap when `equity < 1000`. Not applied because it changes a risk limit.
4. **`tests/test_db.py:32` — test failed for 4 hours of each UTC day.** It compared the ET `session_date` to the UTC date, so it failed from 00:00 to 04:00 UTC. Fixed.
5. **Missing referenced documents.** `SPEC.md` (Security checkpoints, Hard rules) and `research/` (README.md, studies/) do not exist in the repo, so claims could not be checked against them. This audit directory is the first file under `research/`.
6. **Minor.** `options_exec.py:60` uses `date.today()` (server-local date) instead of the ET date. It is harmless during market hours on a UTC host. `loop.py:249-258` re-anchors the kill switch when equity moves more than 50% with no trades. It is safe, but a real gap-down on a position-less account would be hidden.

Checked, no issue: backtest look-ahead (decisions use bar-close data, fills at the next bar's open, prior-session levels and ATR, volume slot average shifted by one session, HTF bars only once complete). Kill switch runs on total equity. Stream callbacks catch their own exceptions. The loop wraps per-trade work in try/except.
